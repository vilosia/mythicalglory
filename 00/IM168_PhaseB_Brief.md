## 0. 本次变更摘要（v0.1 → v0.2）

客户看过原型并反馈后，方向有以下调整：

- **两个方案合并为一个产品**：原「含投注 UI」与「纯指令下注」不再二选一，精华合并到同一套游戏厅里。
- **「Bet Room」正式更名为「游戏厅」**；进入后由原 投注 / 聊天 双 Tab 扩展为 **三 Tab：投注 · 自动投 · 聊天**。
- **自动投重构**：v0.3 方向改为 **Dashboard-first**；第一层显示全部计划与输赢总览，点选 Plan Card 后进入该计划的「投注助手」对话 / 指令上下文；新建计划先展示 **模版 / 预设（Preset）**，再进入自定义。
- **额度发放改为「成员申请 → 群主审批」**（取消群主直接派额，原 UI 作废）。
- **取消 Backoffice**：抽成不再去后台设定，改为 **App 内由群主设定与查看**。
- **强化权限可见性**：成员**永不可见**群主侧任何操作（抽成、额度分配、差额收益等）。
- **投注选号 UI 需易用性改版**；左侧玩法栏**移除「快捷 / 长龙 / 遗漏」**。
- **聊天新增「跟单（Follow）」**：成员可跟随他人已分享的注，但**只通知"已跟单"，不显示跟单金额**。
- 设计系统校正：主蓝 **#126BFF**、警示红 **#EF3939**（v0.1 曾误记为深蓝 / 粉，已更正）。

### 0.1 最新会议反馈补充（v0.3｜2026-06-30）

本次反馈重点不是单点 UI 调整，而是进一步明确 **投注 / 自动投 / 聊天室** 三个 Tab 的职责边界，并将自动投从「多计划横向 Tab + 单计划聊天」调整为更清晰的 **Dashboard-first + Plan Card + 指令操作** 方向。

#### 投注区

- Timer 与 Status 合并显示，不再拆成独立状态和倒计时。
  - 建议文案：`投注时间还剩 11分11秒`。
- Bet amount panel：
  - 移除 `跟投 1 期`。
  - 所有 `单注回报` 文案改为 `可赢`。
- 长龙区：
  - 文案从 `冠军大4` 改为 `冠军大（4期）`，避免「4」的含义不清。
  - 增加 `跟投 / 反投` 功能。
  - 点击长龙 chip 后不应直接下注，应先弹出 card / bottom sheet，让用户设置金额、跟投 / 反投及必要参数，再加入 betslip。
  - 当前初步规则：长龙跟投只跟 `1期`。
- 命名：
  - `跟投 / 反投` 为正式 UI 名称。
  - `斩龙` 只是市场称呼，不作为主要功能命名。

#### 主 Navigation / Header

- `投注 / 自动投 / 聊天室` 三个主 Tab 建议放在 Header 顶部。
- Timer 与 Past Results 只在 `投注` Tab 显示。
- `自动投` 不需要持续显示上方 Status / History。
- `聊天室` 不需要固定显示 Result，优先释放空间给聊天内容。

#### 自动投页面

- 自动投页面应更聚焦于 **指令操作**，减少不必要的 manual click。
- 页面第一眼建议改为 **全部 Plan Listing / Dashboard**，而不是横向 Plan Tab。
  - 原因：Plan 数量多时，横向 Tab 后面的计划会看不到。
- 自动投页面重点显示：
  - 全部 Plan 状态；
  - 输赢金额；
  - 最新执行结果；
  - 是否跟投 / 反投；
  - 是否需要用户操作。
- Message 内容应重点显示：
  - 彩票类型；
  - 金额；
  - 跟投 / 反投；
  - Success / Failed 结果；
  - Winning amount。
- 不需要强调「多少期」作为主信息。
- Timer 如需出现，应考虑以 message / notification 形式呈现，而非固定占用顶部。

#### Plan / Template / Settings

- 新建自动投计划时，应先展示 Template；用户看到 Template 后，才进入 Customize Plan。
- Template 需要增加：
  - Template title name；
  - 外部 preview；
  - Preview word limit；
  - 风险 / 模式标签。
- 目前属于 Simple Mode；后续基础区域需增加 Hard Mode（自定义模式）。
- 自动投 Plan Details Row 需增加 `Send Command`，用于查看完整设定或快速修改。
- Plan 尚未开始 / 未执行：可直接修改 existing plan。
- Plan 已开始：可小幅修改基础设定；保存后必须确认：
  - 马上执行；
  - 下一期才套用。
- 基础设定暂定可修改，但修改后需要 confirmation message。

#### Plan 操作

- 移除 `暂停` 作为常规操作。
- 保留：
  - `急停`；
  - `重启`。
- `急停` 需要 confirmation。
- `重启` 时需要让用户选择：
  - 继续上一回合；
  - 新一轮开始 / 重置设置重新开始。
- 用户场景：若上一轮输了，用户可能希望下一轮重新开始，而不是沿用旧倍投进度。
- Ongoing Plan 增加分享按钮。
  - 其他用户可从分享 widget 中 Save 成自己的 Template，或 Follow 使用。
  - 分享 widget 需要显示 Winning Amount。

#### 聊天室

- 聊天室上方 Result 用途不大，建议移除。
- 聊天室应更接近 full page chat。
- 顶部可改为：
  - 群主 Pin Message；
  - 公告；
  - Search。

#### 群主钱包 / Dashboard

- 群主钱包应成为主 dashboard，而不是普通余额页。
- 客户不理解 `可代投`，建议移除该文案。
- 群主充值无需提供入口，系统会自动更新充值记录。
- Dashboard 参考 Follow Grab，建议显示：
  - Main Wallet；
  - Earn；
  - Total Win；
  - Total 提款；
  - 待审核；
  - Pending amount；
  - Transactions；
  - Member activities。
- 增加：
  - Setting；
  - Time Filter。

#### Search / Pagination

- Search 目前藏在 listing 内，不够直接。
- Search 应放在：
  - 自动投；
  - 聊天室。
- `未结 / 已结` 增加 pagination。
- 外层增加 icon，方便快速切换。

#### 分享下注

- 分享下注建议移至 `全部计划（All Plan）` 页面或更合适的计划/总览上下文中，不要持续挤在手动下注底部。

## 1. 背景与目标

IM168 是一个**聊天平台**，定位为替代微信、Telegram（飞机）等通讯工具，作为彩票玩家社群的私域沟通载体。产品结构为：**频道（Channel）** 内嵌套多个 **群组（Chat Group）**。出于合规考量，**不上架任何应用商店**。

Phase B 的核心目标：把彩票投注能力嵌入聊天体验。其中一个特殊群组为 **游戏厅**——既能手动选号下注、又能用自动化策略、还能在同一房间内聊天与跟单。

**一句话定位：** 聊天是社交粘性，投注是商业闭环；游戏厅把"选号、自动化、社交"三件事收进一个房间的三个 Tab。

## 2. 范围与平台约束

| 项目 | 说明 |
|---|---|
| 平台形态 | 移动 App 为主，**不上架应用商店** |
| 房间结构 | 频道 → 群组；其中 **游戏厅** 群组进入后为 **三 Tab：投注 / 自动投 / 聊天** |
| 依赖系统 | 强依赖**客户既有彩票平台**（账号、额度、赔率、开奖数据来自该平台） |
| 后台 | **取消 Backoffice**。抽成等原本后台的设置改为 **App 内（群主侧）** 完成 |
| Web 端 | Web 端可能因资源下载量大而偏慢，建议优先移动端、评估懒加载 / 分包 |
| 设计系统 | Noto Sans SC；主蓝 `#126BFF`、警示红 `#EF3939`；清爽浅色主题，避免 AI 生成感 |

## 3. 角色与权限层级

| 角色 | 来源 | 主要能力 |
|---|---|---|
| **频道主 / 群主（Owner）** | 由既有彩票平台玩家注册转化而来 | 创建频道 / 群组；持有平台主额度；**审批**成员的额度申请；**代成员投注（群投）**；**在 App 内设定抽成 %**；查看成员注单与剩余额度 |
| **成员（Member）** | 受群主邀请进入 | 在游戏厅手动选号下注、运行自动投计划、在聊天中讨论 / 分享 / 跟单；**向群主申请额度**；查看自己的战绩与钱包 |

**关键机制（后端结算，不对成员暴露细节）：** 成员的下注实际由**群主主账号**在彩票平台**合并代投**为一笔「群投（Group Bet）」，群主从中按设定 % 赚取赔率差额。

### 3.1 权限可见性矩阵（重要）

| 信息 / 操作 | 成员可见 | 群主可见 |
|---|---|---|
| 自己的注单 / 战绩 / 钱包 | ✓ | ✓（成员的） |
| 他人**已分享**的注 | ✓（不含未分享者） | ✓ 全部（含未分享） |
| 他人的下注**金额** | ✗（跟单也不显示金额） | ✓ |
| 成员**剩余额度** | 仅自己 | ✓（**只看剩余，不看已花**） |
| **抽成 % / 抽成收益** | **✗ 永不可见** | ✓ |
| **额度分配 / 审批** 动作 | **✗ 永不可见** | ✓ |
| 群投合并、差额收益 | ✗ | ✓ |

> 原则：群主侧的商业操作（抽成、分配、差额）对成员**完全隐形**；成员只看到"自己的"与"他人主动分享的"。

## 4. 核心功能模块

### 4.1 注册与账号打通（Onboarding）

- 为来自**既有彩票平台**的玩家建立注册转化流程，在 IM168 内开通**群主级账号**。
- 登录后可创建频道 / 群组，并把某个群组设为**游戏厅**。
- （取消 BO 后，原"BO + App 同凭证"简化为：彩票平台身份 → App 账号。具体打通方式见 §7。）

### 4.2 游戏厅 · 三 Tab 总览

进入游戏厅后顶部为三 Tab：

| Tab | 作用 |
|---|---|
| **① 投注** | 手动选号下注的主玩法面板（含分享下注） |
| **② 自动投** | 自动化投注：Dashboard-first 全部计划总览；点选计划后进入该计划的指令 / 助手对话；含模版 |
| **③ 聊天** | 全体成员讨论、分享、跟单的群聊 |

### 4.3 Tab 1 · 投注（手动下注）

- 彩票选号 UI，成员在**已审批额度**内手动选号、下注。
- 保留 **「分享下注」** 开关（成员自选是否公开该注到聊天）。
- **易用性改版**（客户明确要求）：当前选号面板需更易用、易导航——建议精简层级、强化"已选 / 金额 / 确认"的主操作、降低赔率红字的视觉噪音。
- 左侧玩法栏 **移除「快捷 / 长龙 / 遗漏」**；保留 两面 / 1-10名 / 冠亚和（PK10）、两面 / 定位胆 / 龙虎 / 总和 / 跨度（SSC）等核心玩法。
- 游戏类型可扩展（PK10、SSC，未来更多）；用可滚动游戏条 + 全部游戏入口承载。

### 4.4 Tab 2 · 自动投（自动化投注 · 计划制）

重构后的核心交互：

- **自动投第一层 = 全部计划 Dashboard / Listing**；不再以多个横向 Plan Tab 作为第一层，避免计划数量多时后面的计划不可见。
- 每个计划以 **Plan Card** 呈现，显示状态、模式、金额、输赢、最新执行结果与可操作项。
- 点击 Plan Card 后进入该计划的 **「投注助手」对话 / 指令上下文**（agent 式聊天）：成员可用聊天 / 下指令的方式
  - 让助手**按计划下注**、
  - **随时调整 / 重新规划**该计划（改模式、倍投、止盈损等）、
  - 接收**每期更新通知**、
  - 查看该计划的**结果与盈亏（win / lose）**。
- **新建计划**沿用现有自动化设置页：
  - **投注模式：固定选号 / 跟龙 / 反龙**（跟龙=顺长龙方向投，反龙=反向投；取代旧"追龙/斩龙"开关）；
  - 监测盘口、触发长龙阈值（连开 ≥ N 期）；
  - 基础注额、倍投倍率 / 触发 / 上限、中奖后重置；
  - 止盈 / 止损、单期注额上限、累计投注上限；
  - 自动确认下注、每期 / 止盈损 通知。
- 新建计划需先展示 **Template / Preset**，用户看过 Template 后才进入 Customize Plan。
- 在自动投内保留 **「进行中 / 已停止计划列表」**（总览、急停、重启、删除、查看占用额度与盈亏）。
- 移除常规 `暂停`；保留 `急停` 与 `重启`。重启时需询问继续上一回合或重置后重新开始。
- **模版 / 预设（Preset）**：客户喜欢"一键套用"——保存当前设置为模版、套用我的 / 官方模版快速开新计划。
- 多计划可同时运行（注意：需提示累计占用额度，并对同盘口正反向对冲给出警告）。

### 4.5 Tab 3 · 聊天（讨论 · 分享 · 跟单）

- 全体成员在同一房间讨论、提问、分享自己的注。
- **跟单（Follow）**：当有人分享一笔注，其他成员可点「跟单」。
  - 跟单**只通知"X 已跟单"**，**不显示跟单金额**（保护各自下注规模隐私）。
  - 跟单者按自己的额度 / 设定成注（金额自定，不随原注公开）。
- 开奖 / 个人结果以消息形式呈现，**个人优先**（只显示"你"的结果）；**不显示群级合计、不显示群主抽成**。

### 4.6 额度：申请 → 审批（修正原派额逻辑）

- **成员发起额度申请**（请求金额）。
- **群主审批**（同意 / 调整 / 拒绝）后额度才到账。
- 取消"群主直接给成员派一个数字"的旧 UI。
- 群主侧有**待审批列表**；成员侧能看到自己申请的状态。

### 4.7 抽成（App 内 · 群主侧）

- 取消 BO；群主在 **App 内**设定与查看抽成 %（赔率差口径，见 §7）。
- 抽成相关一切（比例、收益）**仅群主可见**，对成员隐形。

### 4.8 群主视图：成员注单 + 钱包分类

- **成员注单**：群主可见每位成员的下注与金额；额度只显示**剩余**（不显示已花）。
- **群主钱包需分类**（建议：平台主额度 / 已审批分配 / 待审批申请 / 差额收益 / 当前可用）。

### 4.9 搜索

- 提供搜索功能（搜消息 / 注单 / 成员等）；**入口可收进右上「⋯」三点菜单**，不占主界面。

### 4.10 游戏类型

- 首批 **PK10（极速赛车）**、**SSC（时时彩）**；复用既有平台玩法与开奖数据；架构上可扩展更多彩种。

## 5. 关键用户流程

### 5.1 额度：申请 → 审批
1. 成员在游戏厅发起额度申请（填请求金额）
2. 群主在待审批列表收到 → 同意 / 调整 / 拒绝
3. 通过后额度到成员钱包 → 可在投注 / 自动投中使用

### 5.2 手动下注（投注 Tab）
1. 选号 → 选金额（手输 / 快捷）→ 选是否「分享下注」
2. 确认 → 计入群投（群主代投，后端合并）
3. 开奖 → 仅显示**你自己**的结果

### 5.3 自动投：Dashboard → Plan → 助手对话
1. 自动投 Tab → 先看到全部计划 Dashboard（运行中 / 已停止 / 今日输赢 / 待处理）
2. 新建计划 → 先展示 Template，再进入 Customize Plan
3. 选择某个 Plan Card → 进入该计划的投注助手对话 / 指令上下文
4. 成员可在对话里调整计划、问进度、看结果；助手按计划逐期下注并通知
5. 已开始计划修改设置时，需确认「马上执行」或「下一期才套用」
6. 触发止盈 / 止损 / 额度上限 → 自动停止；计划进入"已停止列表"

### 5.4 跟单（聊天 Tab）
1. 成员 A 分享一笔注到聊天
2. 成员 B 点「跟单」→ 群内仅提示"B 已跟单"（**不显示 B 的金额**）
3. B 按自己额度成注

### 5.5 开奖结算（抽成对成员隐形）
1. 群投开奖 → 各成员获各自结果（个人视角）
2. 群主侧结算差额收益、抽成 —— **此过程成员不可见**

## 6. UX / 设计考量

- **三 Tab 的边界**：投注=手动、自动投=策略+助手、聊天=社交，职责清晰；三者共享同一房间额度与开奖。
- **投注面板易用性**：减少赔率红字噪音、放大可点标的、精简玩法栏（已去 快捷/长龙/遗漏），让"选号→金额→确认"成为最短路径。
- **自动投助手对话**：把"改计划"变成对话，降低复杂设置的门槛；但助手必须**先确认再下单**、随时可急停，避免失控。
- **跟单的隐私**：只通知不报数，是这套社交玩法成立的关键——金额是隐私，热度是社交。
- **群主商业操作隐形**：抽成 / 分配 / 差额一律不进成员视野，避免信任崩塌。
- **额度只看剩余**：群主看成员"还剩多少"而非"花了多少"，弱化监视感、保留管控力。
- **取消 BO 的影响**：抽成入 App 后，需要群主侧一个简洁的设置项 + 收益视图（仅群主）。

| PK10 / SSC | 极速赛车 / 时时彩 |

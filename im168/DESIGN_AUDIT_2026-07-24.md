# IM168 整站设计一致性审查

日期：2026-07-24  
审查范围：主入口、资讯、频道、游戏厅、投注、自动投、钱包/管理视图，以及 `管理中心_Redesign_v1` 的 6 个相连页面。

## 结论

主原型已经形成稳定的浅色移动端视觉语言，但管理中心独立页面仍停留在旧视觉版本。现有 `DESIGN_SYSTEM.md` 记录了大量逐日修订，规则互相覆盖，无法直接作为团队的唯一标准。

本次将最终规则收敛到新的 `DESIGN_SYSTEM.md`，代码 token 收敛到 `shared/design-tokens.css`，并将管理中心页面对齐到同一套基础视觉与数据格式。

## 主要发现

| 优先级 | 问题 | 影响 | 处理 |
|---|---|---|---|
| P0 | 设计规范存在多轮互相覆盖的旧规则 | 设计与开发无法判断哪条有效 | 已整理为单一权威规范，旧记录归档 |
| P0 | 管理中心使用整块蓝色 Header，主 App 使用白色 Header | 跨页面像两个产品 | 已统一为白底、17px/600 Header |
| P0 | 时间与金额格式混用 | 金额场景难复核，降低信任 | 统一 `YYYY/MM/DD HH:mm` 与两位小数 |
| P1 | 管理中心使用另一套页面底色、文字灰、圆角和头像形状 | 视觉节奏明显断裂 | 已接入共享 token，头像改圆形，卡片改 10px |
| P1 | 一级 Tab 与筛选 Chip 视觉混用 | 层级不清 | 规范明确一级下划线、二级胶囊 |
| P1 | 普通支出使用红色 | 与错误/危险语义冲突 | 统一支出为主文字色，红色仅危险 |
| P1 | 主样式文件仍有大量局部硬编码值 | 后续容易再次漂移 | 建立共享 token；后续按页面逐步替换，不做高风险一次性重写 |
| P2 | 原型 DEMO 控件与产品 UI 同屏 | 评审时容易误判为正式功能 | 规范明确 DEMO 控件只属于演示环境 |

## 页面观察

### 资讯与频道

- 整体色彩、列表密度与底部导航基本统一。
- 正文与次要文字层级清晰。
- 后续需补齐图片 Loading/Error 与空状态一致性。

### 投注

- 玩法密度高，但选号、金额与确认路径可识别。
- 赔率文字应继续保持低对比，避免与选项主文案争夺注意力。
- 紧凑/宽松视图属于局部控制，应保持二级控件视觉。

### 自动投

- 模板卡、策略详情与风险说明形成清晰层级。
- 首次引导弹层的插图和产品卡片语言不同，但属于 onboarding，可接受。
- 策略、计划、执行记录的术语必须按新规范区分。

### 管理中心

- 旧版蓝色顶栏、14px 卡片圆角、方形头像和独立数字字体造成最明显断层。
- 旧页面仍使用「分配额度/回收额度」「今天 09:48」「240」等旧格式。
- 已列为本轮重点对齐对象。

## 后续建议

1. 以后所有新页面先引用 `shared/design-tokens.css`。
2. 每次设计评审按 `DESIGN_SYSTEM.md` 第 11 节逐项检查。
3. 将主样式文件里的近似灰色和局部圆角逐模块替换为 token；不要一次性机械替换 6,000+ 行样式。
4. 建立真实设备 320 / 375 / 430 三档回归检查，并补充键盘焦点与减少动效测试。

## 1. 产品定位

查爆仓 = 帮玩家**决定自动投策略**的数据决策工具，不是单纯的查询工具。
核心价值：把「历史开奖回测」翻译成三个玩家真正会问的问题，并直接把结论接到「快投」和「自动投」两个下注出口。

一句话概括产品逻辑（ChatGPT 评审采纳）：**结论优先，证据按需展开**。玩家不需要研究统计学，只需知道系统建议什么、为什么、以及一键应用。

爆仓数据来源：基于历史开奖数据模拟**倍投回测**得出，仅适用于倍投。系统从触发投注开始按倍数递增计算累计投入与盈亏，统计历史情形中最多需要追投到第几回才能回本——取最大值即「爆仓数据」。

## 2. 两处入口（设计要求：风格统一）

1. **游戏厅 Tab 层级**：投注 / 自动投 / 聊天室 / **查爆仓**（本次新增的第 4 个 Tab）。
2. **新建策略 5 步向导**内「查看爆仓数据」（既有 `#bustModal`，本次未改动，保留备查）。

> 定案（2026-07-11）：Tab 版为主入口，采用本文档规范的全新设计；向导内旧弹窗暂保留。两者视觉将来统一到本规范。

## 4. 表单规范（三项条件）

- **流程定案（2026-07-11）**：进来 → 填条件 → 点「立即查询」→ 出结果。曾尝试「一键分析」（进来只有一个按钮）但**否决**，回归条件查询流程。
- **候选下注回合数已移除**：曾作为第 4 项，因「玩家就是来查该买几回，不该先让他猜一个数」而删除。建议回合数改由系统从数据自动得出（覆盖 ≥95% 历史情形的最小回合数）。
- **跟投 / 反投口径**（与《自动投_功能理解》§3.2 一致）：
  - 跟投 ＝ 长龙形态：同方向连开，顺着投。区间标签「长龙数量区间」。
  - 反投 ＝ 单跳形态：**开大投小、开小投大**（投上一期的反向）。区间标签「单跳数量区间」。
  - **反投界面绝不出现「长龙」字样**，各说各的，不交叉注释。
- 区间用加减 stepper（最低 ≥ 触发 / 最高 ≤ 上限），互相钳制。

## 5. 结果页规范

### 5.1 时间筛选（第一层）
- 「今日 / 3天 / 7天」移到结果页**最顶部**，作为第一层筛选。
- 样式 ＝ Sticky Segmented Tab（吸顶分段控件，灰底轨道 + 白色浮起选中块），非普通按钮。
- 默认选中「7天」；下滚时保持吸顶。
- 切换后整页数据重算（含报告头右侧范围文字）。

### 5.2 分析报告卡（三问三答）
- 升级为「分析报告」气质：深蓝报告头（文件图标 + 标题 + 右侧数据范围），数据不变、只提升高级感。
- 三个标题 ＝ 玩家的三个首要问题：
  1. **要买几回？** — 大数字建议回合 + 省额度替代方案。
  2. **几时开始投比较稳？** — 点名高危时段（14–16 点、21–23 点）。
  3. **哪个玩法最稳？** — 绿点安全项 / 红点在爆项，分两行。
- 每问配 outline 描边图标（循环箭头 / 时钟 / 盾牌），同项目图标语言。

### 5.3 文案层级（全页统一）
- 结构：报告头 → 卡片标题（结论）→ 小字（数据说明）→ 图表（证据）。
- 「标题＝结论在上，小字＝数据说明在下」。例：
  - 近期爆仓趋势 / 「近 7 天共爆仓 4 次，今天 1 次——不算密集，但要留意。」
  - 建议追投回合 · 次数分布 / 「历史数据显示，97% 情况可在 6 期内回本。」
  - 各玩法风险排行 / 「单双、龙虎最稳；冠军·大小最近在爆。」
- 文案要「连十岁小孩都明白」，玩家不用研究数据。

### 5.4 术语（白话化，2026-07-11 定案）
- 「连黑」→ **「连输」**（同一投注项连续未中的期数）。
- 连输超过所设回合数 ＝ **爆仓**。

### 5.5 红黄绿色语言（贯穿全页）
- 绿 `#1D9E75` 安全 / 黄 `#EF9F27` 注意 / 红 `#E24B4A` 风险高。
- 分布图柱子按分界着色：分界前绿、分界那根黄、超出红。
- 玩法列表标签统一 ●风险高 / ●注意 / ●安全（弃用「高危/偏危/较稳」）。

### 5.6 近期爆仓趋势
- 七天日历：绿格没爆、红格显示当天爆几次（带「次」）。
- 下方明细**表格**（对齐注单表格式）：时间 / 投注项 / 连输 / 期号。

### 5.7 建议追投回合 · 次数分布
- 横轴 = 追到第几回合才中（1回…9回），柱上数字带「次」。
- 结论 chip：「6 期内就中：130 次（97%）」+「要追 7 期以上：4 次」。
- 橙色虚线标注系统建议分界（覆盖率 % + 期数）。

### 5.8 各玩法风险排行
- 标题「各玩法风险排行」（原「各玩法爆仓统计」）。
- 每行：玩法名 + 风险标签 + 行内「跟投 / 反投」快投按钮；第二行 = 爆几次 / 最深连输 / 最近时间（期号）。
- 「其余 N 项」聚合行可展开，展开后每项也可快投。
- **投注倒计时**（右上角迷你红环 + 「投注时间还剩 X分X秒」）：查爆仓 Tab 不显示 roundbar，倒计时挪到这里，与投注页封盘时间实时同步。

## 6. 三条下注出口（深度递进）

1. **看完就走** — 保存此查询（快照带保存时间 + 数据范围 + 建议回合数）。
2. **投一注** — 玩法行「跟投 / 反投」→ 复用**长龙快投 drawer**（`streak-drawer`），带风险提示 badge，需输入额度。
3. **建策略** — 底部「生成跟投/反投策略」（文案随查询方向变）→ 启动确认 drawer → 一条自动投开跑。
   - 关联价值：玩法默认只勾**绿色安全项**（自动避开在爆玩法）；回合数 = 建议值；方向 = 查询方向。
   - drawer 复用「极速启用」预算透明规范（玩法/触发/执行/最坏情况/止盈/占用预算 + 未用退回）。
   - 带来源 chip「来自爆仓查询 · 近 7 天 · 时间戳」，供策略详情回溯。
   - 「调整设置」→ 进 5 步向导（参数预填）；「确认启动」→ 直接建好开跑。
   - CTA 文案定案：**「生成跟投策略」**（非「根据以上数据创建…」），左右布局：左「保存此查询」次要、右「生成…策略」主。

## 7. 查爆仓 Tab 内不出现的内容（2026-07-11 定案）

- **不显示开奖历史**（期号 00088 及彩球行）——该 Tab 只讲爆仓数据，与开奖无直接关联的元素一律不放。
- 建议卡内不放「建议预算 / 当前状态」两项、不放卡内「使用建议」按钮、不放免责小字（红线删除项）。
- 免责性质说明仅保留表单顶部「基于历史开奖 · 倍投回测」pill 一处（合规底线）。

## 8. 实现落点（不破坏现有交互）

- 新增 **views/game-bust.js**（`{o:29}`），HTML 随 IM168_VIEWS 注入。
- 逻辑为 **shared/app.js 末尾独立 IIFE**，所有动作用 `bq*` 前缀 + `data-act`，与主模块零冲突。
- Tab 切换、roundbar 隐藏复用既有 `showView`（`data-mainviews` 追加 `bust`），未改主逻辑。
- 快投复用 `streak-drawer`：通过隐藏 proxy 触发主模块 `streakpick`，反投再模拟点 drawer 反投键。
- 生成策略「调整设置」触发既有 `stgnew` 打开 5 步向导。
- 首次引导口径同自动投 `obDrawer`（每会话一次）。
- 倒计时 setInterval 同步 roundbar 的 `.rseal` 文本与 `.sealpie` 进度。
- 样式全部用现有 CSS token（`--blue` / `--tint` / `--line` 等），`bq-` 前缀防污染。

## 10. 开发任务清单（原型 → 生产）

### 10.1 数据接入（替换示例数据）
- [ ] `DS`（今日/3天/7天回测结果）改为后端接口：入参 = 模式 / 方向(跟投·反投) / 区间[min,max] / 时间范围；返回 = 各回合命中次数分布 `bars[]`、七天爆仓日历 `days[]`、爆仓明细 `busts[]`、各玩法风险 `plays[]`、其余安全项数 `restN`。

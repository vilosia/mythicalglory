## 1. 产品定义

IM168 是一个以群组为核心的移动端游戏厅产品，连接成员、群主与自动投注策略。

### 核心目标

1. 让成员以最短路径完成「选号 → 金额 → 确认下注」。
2. 用策略和助手降低自动投注的复杂度，同时保留确认、急停和风险上限。
3. 让聊天、分享与跟单形成社交反馈，但保护个人投注金额隐私。
4. 让群主高效处理审批、成员、交易和抽成，同时对成员隐藏商业规则。
5. 在高频、金额敏感的场景中，以清晰、可信、可复核优先于装饰性。

### 角色与信息边界

| 信息或操作 | 成员 | 群主 |
|---|---:|---:|
| 自己的注单、结果、额度 | 可见 | 可查看成员数据 |
| 他人主动分享的注单 | 可见，不显示金额 | 可见 |
| 未分享注单与金额 | 不可见 | 可见 |
| 成员剩余额度 | 仅本人 | 可见 |
| 抽成比例、收益、额度审批 | 不可见 | 可见 |

原则：成员端强调参与、反馈和可控；群主端强调处理效率、可追溯和风险判断。

## 2. 信息架构

### App 外壳

- 资讯：内容浏览。
- 聊天：频道与群组入口。
- 消息：系统通知和个人结果。
- 我的：个人资料、钱包、历史投注和设置。

### 游戏厅

- 投注：手动选号和下注。
- 自动投：策略模板、本轮运行、执行报告和助手。
- 聊天室：讨论、分享下注和跟单。
- 查爆仓：查询与风险信息。

### 管理中心

- 首页：可分配额度、待审批、成员与最近交易摘要。
- 待审批：上分、下分和入群申请。
- 成员：列表、详情、额度记录、历史投注和管理动作。
- 交易记录：上分、下分、游戏盈利与抽成相关流水。
- 抽成设置：比例、口径、模拟计算与保存确认。

## 3. 设计原则

### 3.1 行动优先

- 每个页面只突出一个当前主任务。
- 金额确认、下注、启用策略等关键动作必须靠近相关上下文。
- 破坏性操作不与主任务争夺视觉权重，只在最终确认时使用红色实心按钮。

### 3.2 状态可复核

- 金额、期号、时间和状态必须可快速扫描。
- 动态操作需同时更新摘要与明细，避免数字不同步。
- 处理中、已完成、已拒绝不可只靠颜色区分，必须同时有文字或图标。

### 3.3 一致但不机械

- 同一层级使用同一视觉语言。
- 一级 Tab、二级筛选、状态标签不可混用。
- 不为对称而加入无用控件；一致性来自位置和行为可预测。

### 3.4 克制的视觉密度

- 蓝色只用于可操作、选中和关键强调。
- 红色只用于错误、危险和拒绝，不表示普通支出。
- 金色只表达额度或收益语义，不作为通用装饰色。

## 4. Design Tokens

Token 的唯一代码来源：`shared/design-tokens.css`。正式产品样式只写入
`shared/styles.css`；根目录 `styles.css` 为未加载的历史文件，不得继续新增样式。

### 4.1 颜色

| Token | 值 | 用途 |
|---|---|---|
| `--blue` | `#126BFF` | 主操作、链接、选中（全平台唯一品牌蓝，外壳不再另用 `#1F6FFF`） |
| `--blue-dark` | `#0B5ADC` | 蓝色文字、按压态 |
| `--blue-tint` | `#E7F0FF` | 选中底、信息强调底 |
| `--blue-line` | `#BBD4FF` | 蓝色系描边（浅蓝底上的边框） |
| `--blue-line-2` | `#CFE0FF` | 更浅一档的蓝描边 |
| `--ink` | `#414141` | 主文字、普通支出 |
| `--muted` | `#6B7280` | 次要文字、时间、说明（白底对比度 4.8:1，达 WCAG AA） |
| `--faint` | `#98A2B3` | 仅限装饰性元素：分隔符、禁用点、空态图标。禁止承载信息文字 |
| `--line` | `#E8E8E8` | 边框、分隔线 |
| `--line-strong` | `#D5D9DF` | 需要更清晰边界时的重分隔线 |
| `--fill` | `#F4F5F7` | 浅灰内衬底：chip、well、输入框底、键帽 |
| `--page` | `#F5F5F5` | 页面背景 |
| `--surface` | `#FFFFFF` | 卡片、导航、弹层 |
| `--positive` | `#16A34A` | 入账、返还、盈利 |
| `--danger` | `#EF3939` | 错误、拒绝、冻结、急停、游戏亏损 |
| `--warning` | `#9A6C00` | 风险提示、需关注 |
| `--gold` | `#C08C38` | 额度、钱包金额、抽成收益 |
| `--hero-grad` | `linear-gradient(180deg, #3D93FF, #2278F5)` | 唯一的英雄卡/选中策略卡渐变 |

状态浅底：

- 信息：`--blue-soft: #EEF4FF`
- 成功：`--positive-soft: #E6F6EE`
- 危险：`--danger-soft: #FDECEC`
- 警告：`--warning-soft: #FFF8E0`

颜色使用规则：

1. 新增或修改样式不得写入与 token 同值或近似的裸 hex，应引用 `var(--*)`。历史样式中的特殊业务色按模块逐步迁移，不做高风险的全文件机械替换。
2. 次要信息文字只能用 `--muted`，不得使用 `--faint` 或更浅的灰。
3. 红色只用于错误、危险、拒绝和游戏亏损结果；普通上分/下分支出保持 `--ink`（由 `shared/app.js` 的 `colorTxNegatives` 按行类型执行）。

### 4.2 字体

```css
font-family: "Noto Sans SC", "PingFang SC", "Microsoft YaHei",
  -apple-system, "Segoe UI", Arial, sans-serif;
```

数字与金额使用同一字体并开启：

```css
font-variant-numeric: tabular-nums;
```

不再混用 JetBrains Mono，避免中文与数字的视觉高度不一致。

### 4.3 字号与字重

**底线规则：任何用户可读文字不得小于 12px。** 唯一例外是数字角标（未读数红点）使用 `--fs-badge: 11px`，且只允许承载 1–3 位数字。Micro（10px）层级已于 v2.1 废除。

| 层级 | 字号 / 行高 | 字重 | 用途 |
|---|---|---:|---|
| Badge | 11 / 1 | 500–700 | 仅数字角标（唯一 <12px 例外） |
| Caption | 12 / 17 | 400/500 | 时间、标签、状态、说明、辅助信息 |
| Compact | 13 / 18 | 500–700 | 长数值自适应压缩档，仅在固定宽度放不下 14px 时使用 |
| Body | 14 / 21 | 400 | 正文、列表信息 |
| Body strong | 14 / 21 | 500 | 行标题、行内金额 |
| Body large | 15 / 22 | 400–700 | 核心阅读场景：聊天气泡正文、投注选项名 |
| Header | 17 / 24 | 700 | 页面标题 |
| Title | 18 / 26 | 700 | 区块或重点标题 |
| Number | 20 / 26 | 700 | 卡片主数字 |
| Display | 28 / 34 | 700 | 钱包、额度池主数字 |

字重只使用 **400 / 500 / 700** 三档，与实际加载的 Noto Sans SC 字重一致；600 已从规范移除（此前声明 600 的位置浏览器实际渲染为 700）。

例外字号只允许用于走势图和营销型引导插图文字，并需在组件内声明；游戏球号使用 12px（球体 21px）。

### 4.4 间距

采用 4px 基础网格：

`4 / 8 / 12 / 16 / 20 / 24 / 32`

- 页面水平边距：12px。
- 卡片内边距：12px 或 16px，同一页面不得混用。
- 卡片间距：12px。
- 列表行垂直内边距：12px。
- 标题与内容：8–12px。
- 组件内部紧凑间距：4–8px。

### 4.5 圆角

| Token | 值 | 用途 |
|---|---:|---|
| `--radius-sm` | 8px | 小按钮、Tag、输入内部元素 |
| `--radius-md` | 10px | 卡片、输入框、常规按钮 |
| `--radius-pill` | 999px | Chip、余额标签、状态标签 |
| `--radius-sheet` | 15px | Bottom sheet 顶部 |
| `--radius-device` | 36px | 原型手机外框，仅演示环境 |

头像统一为圆形，不使用圆角方形。

### 4.6 边框与阴影

- 常规边框：`1px solid var(--line)`。
- 内容卡优先用白底与页面灰底区分；仅在边界不清时加边框。
- 产品界面不使用大面积投影。
- 阴影只用于浮层、Popover、Toast 和演示手机外框。

## 5. 页面骨架

### 5.1 普通详情页

`Status Bar → Header → Content → 可选固定 CTA`

- Header 高 54px，白底，下方 1px 分隔线。
- 返回图标左侧触控区至少 44×44px。
- 标题 17px / 700。
- 右侧只放与当前页面直接相关的操作。

### 5.2 列表页

`Header → 一级 Tabs → Utility Row → List → Pagination`

- 搜索不放在 Tabs 上方。
- Utility Row 左槽为搜索或动态计数，右槽为排序或时间筛选。
- 右侧筛选器宽 104px，文字左、箭头右。
- 搜索、筛选、Tab 变化后回到第 1 页。
- 移动分页使用 `‹ 1 / N ›`，不使用桌面页码组或无限滚动。

### 5.3 游戏厅

`Game Header → 一级 Tabs → 期号/开奖 → 玩法区 → 注单入口`

- 顶部余额使用灰底金色金额 Chip。
- 玩法切换是二级筛选，不使用一级 Tab 的下划线样式。
- 选择结果、金额和确认按钮保持在同一任务路径内。

### 5.4 Dashboard

`Header → 核心数字 → 待办 → 摘要卡 → 最近记录`

- 首屏先展示需要判断或处理的内容。
- 摘要与完整列表通过「查看全部」连接；入口固定在 Section 标题右侧。
- 管理列表页采用两段式表面：Header 与主 Tab 属于连续白色导航区；Tab 下方立即进入 `--page` 灰色数据区，搜索与筛选作为数据区顶部工具栏。
- 成员等同构条目使用一个白色列表容器加行分隔线；审批等独立任务使用分开的白色任务卡，不叠加第二层白色外框。
- 三项财务摘要不得固定塞入三等分窄列，也不使用不对称的 2＋1 拼接块。钱包统一使用全宽键值行：标签与笔数在左、金额在右，确保任意金额长度不影响其他指标。

## 6. 组件规范

### 6.1 Header

- 白底、深色文字、17px / 700。
- 禁止管理中心单独使用整块蓝色顶栏。
- 群组名是次要上下文，使用 12px 灰色或浅灰 Chip。

### 6.2 一级 Tabs

- 容器高度 41px，底部固定一条 1px 分隔线；分隔线属于 Tab 组件，不由下方内容补充。
- 选中项使用深色加粗文字 + 居中的 `26 × 3px` 蓝色下划线。
- 每项触控区至少 44px 高。
- 用于页面主分类：投注 / 自动投 / 聊天室 / 查爆仓，以及未结 / 已结等内容面板切换。
- 下钻页隐藏游戏厅一级 Tabs，不重复展示。

### 6.3 二级筛选 Chip

- 可见高度 30px，圆角 15px，水平内边距 12px，同组选项间距 8px；外围布局保证触控区至少 44px。
- 未选：白底、`#9CA3AF` 文字与 1px 描边，12px / 400。
- 选中：`#EEF4FF` 浅蓝底、`#126BFF` 文字与 1px 描边，12px / 500。
- 宽度随文案自适应，不为了对称强制等宽。
- 用于玩法、类型或局部范围筛选，不替代一级 Tabs。
- 玩法分类、流水类型、投注来源和结果筛选共用外观，但保留各自的正确交互语义。
- 搜索框旁的高级筛选触发器使用 40px 工具栏规格；与 30px 快速筛选同排时改用 30px 紧凑工具按钮，默认灰色，只有存在已应用条件时使用蓝色。

### 6.4 Button

| 类型 | 样式 | 使用 |
|---|---|---|
| Primary | 蓝底白字 | 当前唯一主动作 |
| Secondary | 灰/白底深字或蓝描边 | 同级次动作 |
| Ghost | 无底或弱边框 | 取消、低优先级 |
| Danger | 红底白字 | 最终危险确认 |

- 常规高度 40px，最小触控高度 44px。
- 同一行双按钮等宽。
- 危险入口可用红色文字或描边；危险最终确认才用红色实心。
- Disabled 需降低对比并禁用点击，不只改变颜色。

### 6.5 Card

- 白底、10px 圆角、12–16px 内边距。
- 避免卡中套卡。
- 同一张卡只承载一个语义单元。
- Hero 卡可用浅蓝底，但管理中心与钱包主金额默认白底。

### 6.6 List Row

- 行标题 14px / 500。
- 时间与说明 12px / 400 / `--muted`。
- 金额 14px / 500，使用等宽数字特性。
- 行间使用 1px 分隔线，首尾不额外加线。
- 有下一级详情才显示 Chevron。

### 6.7 Form

- 输入框高度至少 40px，10px 圆角。
- Label 12px / `--muted`，值 14px / `--ink`。
- 金额输入实时格式化为千分位 + 两位小数。
- 错误信息紧邻字段，使用危险色与明确文案。
- Placeholder 不能代替 Label。

### 6.8 Status Tag

- 必须包含文字；关键状态同时带图标。
- 自动投状态词只使用：未启用、运行中、已暂停、待结算、已急停、已完成、执行异常。
- 「监测」只描述运行中的行为，不作为独立状态名称。
- 处理中：蓝底白字。
- 已完成：浅蓝或浅绿底，深蓝/绿色字。
- 已拒绝：浅灰底灰字，整行可同步降级。
- 冻结、失败、急停：危险色。

### 6.9 Bottom Sheet / Modal

- 低风险选择、编辑：Bottom sheet。
- 金额确认、不可逆确认：居中 Modal 或确认 Sheet。
- 当前产品没有拖拽关闭手势，Bottom Sheet 不显示把手线，避免暗示不存在的拖拽能力。
- 未来若实现拖拽，只允许可拖拽的 Bottom Sheet 使用统一 `36 × 4px` 把手；Modal 与侧边 Drawer 不显示。
- 双按钮横向等宽：取消在左，主动作在右。
- 点击遮罩、返回键与关闭按钮行为必须一致。

### 6.10 Empty / Loading / Error

- 空状态包含：简洁图标、说明、可选下一步。
- Loading 保留页面骨架，避免整页跳动。
- Error 说明发生了什么、数据是否受影响、用户可做什么。

## 7. 内容与数据格式

### 7.1 术语

- 产品内统一使用「额度」，不使用 Credit、余额或金额指代账户额度。
- 额度方向统一为「上分 / 下分」。
- 页面名称统一为「历史投注」。
- 钱包中同时包含上分、下分和游戏盈亏的记录区统一称「额度明细」，不称「额度往来」。
- 自动投的规则集合统一称「策略」；策略的一次执行过程称「本轮运行」。
- 用户界面不再使用「计划」指代策略或执行过程。

### 7.2 金额

- 所有额度金额：`240,000.00`。
- 正向入账可显示 `+1,200.00`，使用绿色。
- 支出显示 `−200.00`，保持主文字色。
- 红色不得用于普通支出。
- 百分比、期数、注数不补两位小数。

### 7.3 时间

- 财务流水、投注记录和审批记录使用绝对时间：`2026/07/07 14:32`。
- 聊天消息使用语境时间：当天为「今天 09:48」，前一天为「昨天 21:08」，更早为「2026/07/05 21:08」。
- 策略的实时执行动态在已明确日期筛选范围时，单行可只显示 `09:40`；历史报告、导出及记录详情必须显示完整绝对时间。
- 实时状态和最近使用等非账务提示可使用「今天」「刚刚」；进入记录详情后必须显示完整绝对时间。
- 仅日期：`2026/07/07`。
- 日期快捷筛选统一为：今天 / 最近 7 天 / 本月 / 自定义日期。
- 不提供「最近 30 天」或「全部时间」作为快捷项。
- 成员无投注记录显示「尚无投注」。

### 7.4 文案

- 按钮使用动作动词：确认下注、启用策略、通过申请。
- 避免模糊词：好的、确定、处理。
- 危险动作需写明对象和结果：确认冻结成员、确认删除策略。
- 成员端不出现抽成、差额、代投合并等群主商业信息。
- 快捷指令只执行 `/` 命令；中文输入只用于搜索指令名称，输入框必须明确说明。

### 7.5 自动投分享

- 分享资格必须同时满足：已观察至少 10 个真实开奖期，并且至少触发 1 次。
- 10 期但 0 触发时不得分享，入口需说明仍缺少一次触发。
- 分享后的策略卡实时同步运行状态；急停并完成结算后固化最终快照。

## 8. 交互与动效

- 标准状态变化：120–180ms。
- Drawer/Modal：200–240ms。
- 审批通过后的卡片收起：约 230ms。
- 使用统一缓动：`cubic-bezier(.22, 1, .36, 1)`。
- 尊重 `prefers-reduced-motion`，关闭非必要位移和缩放。
- 动效用于解释状态变化，不用于延迟操作。

## 9. 可访问性

- 正文与背景对比度至少 4.5:1，大字至少 3:1。
- 可点击区域至少 44×44px。
- 不只靠颜色传递状态。
- 图标按钮必须有可读名称。
- Tab、Dialog、导航和表单使用正确语义。
- 键盘焦点清晰可见，焦点顺序与视觉顺序一致。
- 动态 Toast、审批结果和错误使用合适的 live region。

## 10. 响应式与原型环境

- 产品基准宽度：375px。
- 支持 320–430px，不允许主内容横向滚动。
- 安全区使用 `env(safe-area-inset-*)`。
- 手机外框、状态栏时间与左侧 DEMO 控件只属于原型展示，不属于产品 UI。
- 大于 768px 时可保持手机预览居中；真实 Web App 应使用流式容器，而不是固定设备框。

## 11. 页面级一致性检查

## 12. 治理规则

1. Token 变更只修改 `shared/design-tokens.css`，并在本文件同步说明。
2. 新组件先复用现有结构；确需新增时，先定义用途、状态和适用层级。
3. 禁止以日期追加互相覆盖的规则；规范变更直接更新对应章节。
4. 历史决策记录在 `DESIGN_SYSTEM_HISTORY.md`，不再作为实现依据。
5. 独立探索稿应放入明确的实验目录，不得覆盖正式页面的 class 或 token。

## 0. 设计原则

玩家打开执行动态只想回答四个问题（按频率）：

1. **我现在赚还是亏**（累计盈亏常驻可见）
2. **这期投了多少、下期要投多少**——倍投 10→20→40→80 的递增是玩家最紧张也最关心的数字
3. **哪些项目还在跑、哪些停了**（Active / 已停一眼分清）
4. **系统是不是照我设置的在跑**（操作回执 = 信任凭证）

**事件可以多，模板必须少**：所有事件收敛到 2 大类 3 个模板，用「同一模板 + 文案变体」覆盖。
每多一种报告类型，玩家要多学一种格式，QA 要多测一条路径。

## 1. 体系总览：2 大类 · 3 模板

| 模板 | 底色 | 用途 |
|---|---|---|
| **T1 设置报告** | 浅蓝 `#EAF3FF` | 玩家动过设置的凭证：创建 / 修改（含官方模板来源标签） |
| **T2 状态报告** | 浅蓝 `#EAF3FF` | 运行状态改变：启用 / 急停 / 暂停 / 结算（/ 自动停止，见 §6） |
| **T3 每期执行卡** | 白 | 每期一张卡，**三态流转**：计划下注 → 待开奖 → 已结算；监测期/历史期为同模板收起行 |

指令类查询回复（查状态 / 今天盈亏）保留近白底 `#FBFDFF`「指令报告」，不属于以上两类。

## 2. 事件 → 模板映射（含删减）

| 事件 | 报告 | 说明 |
|---|---|---|
| 设置策略 ＋ 保存策略 | T1「策略已创建」 | 合并一条：未保存的设置不存在 |
| 修改策略（向导 / 重启前 / 指令） | T1「设置更新」 | 改了什么 + 新设置全文；同时摘掉「官方」标 |
| 使用官方策略 | T1「策略已创建」+ `官方模板` 标签 | 来源标记，不是新类型 |
| 启动 / 急停后再启动 | T2「策略已启用 · 重新开始 / 继续上一回合」 | 同一模板两个变体 |
| 急停（按钮 / 指令）＋其未结结算 | **合并为一条**「已急停」，展开 = 急停当期注单（见 §4.5） | 待结算 → 开奖后同条更新为最终盈亏，**不另发结算报告** |
| 暂停（指令） | T2「已暂停」 | |
| 扫描到投注项（原报告2） | T3 期卡**「计划下注」态** | 玩家干预窗口，见 §4 |
| 开始下单（原报告3） | T3 期卡**「待开奖」态** | 同一张卡状态流转 |
| 每期执行结果（原报告4） | T3 期卡**「已结算」态** | 同一张卡状态流转 |
| ~~删除策略~~ | **✂ 不进执行动态** | 流随策略删除而消失，写给谁看？toast 确认即可 |

## 3. 报告数据结构

`plan.reports` 数组，新报告 `unshift` 到头部（流内最新在上）：

```js
{
  t:     '09:45',          // 显示时间（原型为 mock 字符串）
  title: '设置更新',        // 标题；缺省时 set:true → '设置更新'，否则 '指令报告'
  s:     '止盈 100 → 300 · 下一回合生效；新设置：…',  // 正文
  set:   true,             // true = 浅蓝底（T1/T2 操作回执）
  r:     '已确认',          // 右侧状态文案（未启动/运行中/已急停/已确认…）
  pnl:   39,               // 可选；有值时右侧显示红绿盈亏数字，覆盖 r
  src:   '官方模板'         // 可选；标题后加琥珀色来源小标签
}
```

写入点一览（`shared/app.js`）：

| 函数 / 分支 | 写入的报告 |
|---|---|
| `saveStg`（新建） | T1 创建（`src` 按 `cur.official`）；「保存并启动」时叠加 T2 启用 |
| `saveStg`（编辑）→ `logSetChange` | T1 设置更新（`official=false`） |
| `stgqconfirm`（模板快速启动） | T1 创建+官方模板 与 T2 启用·重新开始 两条 |
| `stgstartgo`（未启动→启用） | T2 策略已启用 |
| `stgresumego`（重启二选一） | T2 启用·重新开始 / 继续上一回合 |
| `doConfirm`（急停确认） | T2 已急停 |
| `execCmd`（/ 指令） | 改设置→T1（isSet）；暂停/急停→T2；查询→指令报告（近白底） |
| `scheduleSettle`（30s 模拟结算） | T2 未结注单已结算（`pnl` 显示最终盈亏） |

## 4. T3 期卡 · 三态流转

```
① 计划下注（原报告2）──封盘──▶ ② 待开奖（原报告3）──开奖──▶ ③ 已结算（原报告4）
   玩家干预窗口                    注单不可撤回                  结果并入累计
```

**同一张卡状态流转，不发新卡。**

### ① 计划下注态（仅运行中策略显示，默认展开）
- 琥珀色倒计时条：「**0分42秒** 后封盘自动下单 · 期间急停或修改设置，都在下单前生效」
  —— 扫描到下单之间的时间窗是玩家的**干预窗口**，必须明说
- 关键数区：见 §4.6 统一版式（首期计划态字段裁剪；其余运行态 5 格）
- 投注项表格（见 §5）；可赢按 **1.99 赔率**估算（可赢 = 金额 × 0.99）
- 底注：共 N 项 · X 跟投中 · Y 新触发 · Z 已停 · 若未中下期金额见红字
- 收起行也保留红色倒计时：`3 项 · 计划投入 370 · 0分42秒后下单`，右侧「可干预」

### ② 待开奖态
- 状态 chip 转琥珀「待开奖」；文案反向说明：「注单已提交、不可撤回；此时急停只影响后续期」

### ③ 已结算态
- 每项 命中 +X / 未中 −X；标题右侧本期盈亏（红/绿）
- 底注：命中项该组倍投结束回到监测；未中项按倍数进入下一回合（红字 = 下期金额）；**距止损还剩多少**

### 监测期 / 历史期
- 同模板的收起行：`第088期 · 监测｜未达到长龙 ≥ 3，本期未下注｜监测中`
- 点开显示扫描说明或该期简版明细表；不是独立报告类型
- 向下滚动加载更早记录（每次 +5，封顶 25 条），到底显示「已显示今日全部记录」

### 4.5 急停/结算合并报告 · 急停当期注单（`pxLedger`）
急停后置顶一条「策略已急停 · 后续投注已停止」，默认展开，右侧显示「3 注待结算」；开奖后同条更新为「已结算」（不另发结算报告）。结构：
- 关键数区（v16 起，见 §4.6）：2 格 **未中注数 · 计划进度**。累计投入与累计盈亏只在对应策略卡展示一次；不显示命中、收尾原因。
- **完成计划 · 结算**（系统触发止盈/止损/回合跑完的自然收尾）复用本结构：标题改「计划完成 · 已结算」、末期账本行显示已结算结果、底注改为完成版文案。
- **只展示急停当期**，历史期仍保留在下方 Feed，避免同一期重复两次；当期行 `data-act="stgpxl"` 可展开：
  ```
  期号   注数  本期投入   结果
  第090  3    210       待开奖   ← 琥珀高亮
  ```
  展开后使用四列表头「投注项 / 回合 / 金额 / 可赢（结算后为盈亏）」，不重复显示每注「待开奖」Chip。
- 底注：未提交注单不可撤回、按开奖结算，开奖后本条同步更新。

### 4.6 指标区统一版式（v14）· 弹性等分格

`pxCard`（运行中三态）与 `pxLedger`（终态）共用同一套 `.px-key` 等分格（格 `.k`），字段随状态自适应，不用大数字 Hero、不用语境行。累计投入与累计盈亏不进入单条 Feed 的指标区。

| 状态 | 关键数格 | 格数 · 佈局 |
|---|---|---|
| 首期计划 | 预计盈利 · 〔本期计划 30·3项〕 | 2 · 一行两列 |
| 计划下注 | 〔本期计划 210·3项〕· 计划进度 | 2 · 一行两列 |
| 待开奖 | 〔本期投入 210·3项〕· 计划进度 | 2 · 一行两列 |
| 已结（单期） | 〔本期投入 210·3项〕· 命中 · 计划进度 | 3 · 一行三列 |
| 急停 / 完成计划 | 未中注数 · 计划进度 | 2 · 一行两列 |

规则要点：
- **预计盈利**：只在首期计划显示（本期预估 @1.99）；运行后的累计盈亏由对应策略卡统一承载。
- **合并格**：「本期(计划)投入」与「投注项目数量」并为一格，值「金额 · N项」（如 `210 · 3项`）。
- **命中**：仅「已结（单期）」显示（本期命中 X/Y）；终态不显示命中。
- **未中注数**：仅终态（急停 / 完成计划）显示，值为「累计未中注数 / 已投注总注数」；不再使用容易误解的「爆仓次数」。
- **计划进度**：计划已执行期数（plan-level，序数展示如「第五轮」）。策略跑到止盈/止损为止、**无固定回合上限**，故**只显示已进行轮次、不带分母**（不存在「总回合」参数）；且**非各投注项各自的倍投回合**；首期计划不显示。
- **首期计划裁剪**：无历史，隐藏爆仓 / 命中 / 计划进度，仅保留预计盈利与本期投入 2 格。
- **不显示**：距止损语境行、完成计划的收尾原因（均已移除）。

## 5. 投注项独立回合规则（核心）

**每个投注项独立触发、独立计回合**——不同市场的长龙在不同期形成，所以同一期里各项处于不同回合。
倍投进程**按项目逐行显示**，表格五列：

```
状态chip │ 投注项 · 进程 │ 回合 │ 金额 │ 可赢/盈亏
🔵跟投中   冠军 大          第5回   160   158.4
           10→20→40→80→[160]
🔵跟投中   亚军 单          第3回   40    39.6
           10→20→[40]
🟢新触发   第五名 小        第1回   10    9.9
⚪已停     第三名 龙        2回止   —     长龙中断
```

- 当前金额**加粗**，下期金额**红色**（`<em>` 标红）——第 5 回的 160 与第 1 回的 10 并排，玩家对倍投递增有直观感知
- 固定投显示 `固定 ¥N/注`，无进程串
- **已停项必须列出**：上期有投、本期因规则未延续（长龙中断 / 单跳中断 / 超出区间），灰色置底；「第 N 回止」放在回合列

### 5.1 关键不变量：回合数 ≤ 已运行期数
一个投注项的回合数 = 它**已连续下注的期数**。策略只跑了 5 期，任一项最多第 5 回，绝不会出现第 6/7 回。
`pxItems` 中 `PX_PERIODS=5` 是演示的"已运行期数"上限，各项回合取 `Math.min(该项已连续期数, PX_PERIODS)`。真实实现由引擎按实际连投期数推导，天然满足此不变量。

### 5.2 已停项计入其活跃各期盈亏
已停 ≠ 未中：
- **已停** = 该期**没下这注**（金额空、盈亏空，标停因）
- **未中** = 该期**下了但输**（有金额、有 −盈亏）

已停项在它**活跃的各期**（下注过的期）是真金白银投入的，**必须计入那些历史 Feed 的本期投入、盈亏与未中注数**；「已停」只标在它实际停下的那一期。如第三名龙在 086/087 作为未中计入，停在 087（2回止），088 起不再出现。

### 5.3 未中注数（`pxBust`）
口径：**累计未中注数 / 已投注总注数**。它是历史结果统计，不再称为「爆仓次数」；终态摘要显示为 `8 / 11 注`。

### 状态 chip 语义

| chip | 颜色 | 含义 |
|---|---|---|
| 跟投中 / 待开奖 | 蓝 | Active，本期有注 |
| 新触发 | 绿 | 本期首注（第 1 回） |
| 已停 | 灰 | 上期有投、本期未延续 |
| 命中 | 绿 | 已结算赢 |
| 未中 | 红 | 已结算输 |

## 6. 实现说明与演示数据口径

- **展开状态**：`pxOpen{}` 按 key 记忆，`data-def` 携带默认值；期卡/报告点 `data-act="stgpx"`、账本期行点 `data-act="stgpxl"`（含 `stopPropagation`，不误collapse父报告）；均 `updateFeed()` 局部重渲染
- **演示数据**（原型 mock，接真实引擎时替换 `pxItems`/`pxStake`/`pxProg`/`pxLedger`/`pxBust`）：
  - `PX_PERIODS=5`：各项回合 5 / 3 / 1（新触发）+ 1 项已停（2回止），全部 ≤ 5（见 §5.1）
  - 历史 Feed 086–090：本期投入 20/40/50/100/210，累计统计由策略卡承载，最深回合 5，未中注数 8/11
  - 已结算卡：首项命中、其余未中；倒计时为静态「0分42秒」（未与开奖引擎同步）
  - 赔率 1.99；历史期明细为简版演示表
- **完成计划 · 结算**（达到止盈/止损/回合跑完的系统自然收尾）：复用急停「当期注单」结构（见 §4.5、§4.6），非新组件
- **未实现（模板已支持，等真实引擎）**：进入/退出暂停时段的 T2 报告——换文案，不加新组件
- 运行中：计划卡（090）全量 + 已结算卡（089）+ 监测/历史收起行；已急停：置顶「已急停」当期注单（合并结算），历史期继续留在下方 Feed

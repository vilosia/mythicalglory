## Current Truth（下一位 AI 必须先读）

### 1. 产品与角色

- IM168 是面向彩票私域社群的 IM 产品，Phase B 把聊天、游戏厅、下注、自动策略、额度结算与群主管理串成同一条产品链路。
- 成员主路径：资讯 / 聊天群组 → 游戏厅 → 投注 / 自动投 / 聊天室 / 查爆仓 → 钱包与额度申请。
- 群主主路径：聊天列表的置顶「幸运组 · 管理面板」→ 管理中心 → 待审批 / 成员 / 成员详情 / 抽成设置 / 额度往来。
- 无 URL hash 时默认打开资讯 `view-news`；URL hash 可直达页面并在刷新后保留。

### 2. 当前文件与修改边界

- `index.html` 是约 300 行的运行外壳：手机 chrome、底部导航、共享 Drawer / Modal 与脚本引用。它不是完整页面内容。
- `views/*.js` 保存各业务页面的 HTML 模板；改哪个区块优先改对应文件。
- `shared/app.js` 保存路由、事件委托、前端状态与跨页联动。
- `shared/styles.css` 保存全部共享与页面样式；设计统一优先复用现有组件，不另造独立视觉体系。
- `views/*.js` 的页面片段位于 JS 模板字符串内，禁止写入反引号或 `${}`。
- 本目录当前可运行事实优先于旧规格；不要从 `管理中心_Redesign_v1/` 或历史备份整页覆盖现行文件，只可定向迁移明确指定内容。

### 3. 当前游戏厅

- 游戏厅固定为四个 Tab：**投注 / 自动投 / 聊天室 / 查爆仓**。
- 顶部游戏 chrome 在这四页显示；开奖 Round Bar 只在投注页显示。
- SG飞艇 / 时时彩标题、开奖结果与长龙示例会随游戏切换；仍为前端 mock，尚未连接实时开奖数据。
- 钱包入口位于游戏厅 Header，当前显示额度 `240,000.00`。
- 历史投注已结页的结果、来源与日期会共同过滤 Listing；日期支持今天、最近 7 天、本月及自定义范围，查看更多数量按筛选后剩余记录计算。

### 4. 当前成员钱包

- 钱包使用「额度」业务语言，不采用旧版 `可用 Credit / 申请 Credit / 申请提款` 信息架构。
- 蓝色 Hero 展示「当前额度」、上分 / 下分 CTA、今日盈亏与今日未结；不显示设置四点，也不展示自动投占用明细。
- 上分与下分各自同一时间只允许一笔待审核申请；待审核卡独立放在 Hero 下方。
- 主记录 Section 名称为「额度往来」，包含已完成的上分、下分与游戏盈亏。
- 待审核和已拒绝申请不进入已完成流水或合计；审批通过后才写入额度往来。
- 用户可见的 pending 状态统一写「待审核」；旧记录中的「处理中 / 待确认」只代表历史版本。
- 日期范围控制汇总与明细；类型 chips 只筛选明细，不改变同一日期范围的总体汇总。
- 钱包、游戏厅余额 pill、申请金额页和审批通过后的额度已有部分前端联动，但刷新后不会持久化。

### 5. 当前管理中心

- 采用单页纵览，不使用旧三 Tab 管理架构。
- Header 为「管理中心 / 幸运组」并保留抽成设置入口。
- 蓝色 Hero 展示「我的额度」、今日抽成、累计抽成与抽成比例。
- 成员和待审批使用左右并排入口；待审批红点只表达真实待办。
- 「额度往来」内联在管理中心首页，汇总上分、下分和额度池净变动，只统计已完成交易。
- 成员列表支持搜索、状态筛选、排序与查看更多；现行状态为活跃、不活跃、已停用。
- 成员详情使用同源蓝色资金 Hero，展示当前额度、累计总盈亏、群主累计抽成；下方为成员视角额度往来。
- 低频成员管理动作进入成员编辑页；「冻结成员」现行文案统一为「停用游戏权限」，不会冻结现有额度或阻止已下注单结算。
- 不存在群主主动「回收额度」动作；额度返回群主通过成员发起「下分」完成。

### 6. 当前审批

- 待审批只处理上分和下分，分别放在两个 Tab；不混入入群申请。
- 审批卡使用两行两列信息：左侧姓名 / 申请时间与次数，右侧申请金额 / 当前额度。
- 可分配额度不足时禁用「通过」，仍允许拒绝。
- **现行交互是即批即走**：点击通过或拒绝后立即 Toast、移除卡片、更新计数并让下一张上移。
- 旧版居中二次确认、拒绝原因输入和处理后原位停留均不属于当前实现，除非 client 重新明确要求。

### 7. 当前抽成设置

- 默认选择「按成员投注」，说明为按成员投注额度计算抽成；另一方式为按成员盈利。
- 现行示例比例为 `0.0008%`，支持 preset、自定义和保存脏状态。
- 设置与试算完全分离：主页面只保存抽成方式和比例；试算在独立 Drawer 内完成，不进入保存状态。
- 保存修改使用 Bottom Drawer 确认，并说明下一期生效、历史数据不重算。
- 成员端不得看到群主抽成、抽成比例或试算结果。

### 8. 当前自动投与查爆仓

- 自动投现行为策略中心：固定三张策略卡位、官方模板 / 自定义策略、启用 / 急停 / 重新启用 / 完成生命周期，以及执行动态与筛选 Drawer。
- Active 只代表当前查看的策略，不代表正在运行；策略状态必须由状态图标和事件文案表达。
- Feed 只追加不改写历史；投注、开奖结算、异常、暂停、恢复、急停和完成使用独立事件语义。
- 策略分享代表「策略 + 当前本轮运行」；重新启动产生新 `runId`，旧轮卡片保留并冻结最终数据。
- 聊天分享卡展示**本轮累计投入、本轮盈亏与触发次数**；实时详情继续公开当前监测窗口、每次实际投入和对应的已结算盈亏，为绝对成绩提供可核对的资金基数。仍不展示分享者的钱包余额、上分 / 下分记录、总资产或其他策略资金。
- 实时详情的「策略动态」保留每个已开奖期的逐期记录，包括「检测条件未满足」状态；列表采用「时间 / 期号 / 投入 / 盈亏」四列，Drawer 最多显示最近 5 期。超过 5 期时点击「查看全部」，在同一个固定高度 Drawer 内切换为完整动态内容，并支持全部 / 盈利 / 亏损 / 待开奖 / 未触发筛选与每次加载 20 条；返回后恢复策略详情，外框高度不跳动。
- 分享详情的策略设置固定压缩为 4 格：监测条件、投注范围（玩法 + 方向）、投注方式（固定 / 倍投及金额结构）、风险控制（最大单注、所需额度、止盈止损）。
- 套用会生成接收者自己的独立策略副本；来源策略的基础金额、倍投与风控设置会先显示给接收者，接收者可选择直接套用或编辑后使用，并在后续确认层决定保存 / 启用。分享者的盈亏、触发次数、运行进度和钱包状态不会继承。每位玩家最多三张策略，并有重复套用保护。
- 查爆仓为双屏数据工具：查询条件 → 结果分析 → 调整方向 / 长龙 / 时间 / 候选回合 → 保存查询或生成策略。

### 9. 当前设计系统

- 主蓝 `#126BFF`、危险红 `#EF3939`、正收益绿 `#1FA971`、资金 / 抽成金 `#C08C38` 均有功能语义，不合并成单一强调色。
- 中文使用 Noto Sans SC；金额、赔率、期号、计数和计时使用等宽数字处理。
- 管理中心、成员详情与钱包共享蓝色 Hero、白色 Section、紧凑列表和同一套筛选 / 日期组件。
- 禁用态统一为主题蓝底白字并降低透明度；危险操作只在最终确认层使用实心红色。
- 字重只使用 `400 / 500 / 700`；Figma 文字基线为标题 `18px`、默认正文 `14px`、辅助文字 `12px`、时间 / 微型信息 `10px`，禁止小于 `10px`。超过 18px 只用于金额、余额、盈亏、统计数字及非文字图标。
- 标准文字色：暗灰 / 黑 `#414141`、浅灰 `#9CA3AF`、蓝色 `#126BFF`；红、绿、金、紫等业务 / 状态色继续保留。蓝底上的白字与浅蓝反白属于对比度例外。
- 圆角层级：Drawer 顶部 `15px`、页面第一层 / 默认外框 `10px`、筛选控件 `10px`、外框内第二层 `8px`、大 CTA `10px`、小 CTA `8px`；状态 pill、头像与圆形按钮不套用卡片圆角。
- 操作型图标统一为 inline SVG；成员 ID / 交易编号的复制图标按 client 指定使用 `CopyIcons-20px.png` 视觉。Drawer 不显示重复的右上关闭图标，保留遮罩、取消或底部 CTA 退出。
- 设计原则：总览负责看、任务页负责做；状态和金额必须有单一主焦点；不为填空而新增入口或图标。

### 10. 当前技术状态与已知限制

- 当前是单机前端 Prototype，业务数据主要来自 DOM 与内存变量，不是生产级状态管理。
- 上下分申请 → 群主待审批 → 通过后更新钱包 / 额度往来 / 成员名册已有部分联动，但刷新即恢复 mock。

- 真实产品仍需补齐 loading、网络失败、重复提交、余额竞争、撤销 / 退款、空态和异常恢复。

## Unified 额度 State Model（下一阶段实施方向，已确认）

当前代码尚未完全重构到此模型；后续新增或修正额度流程时以此为目标，避免继续依赖跨页 DOM 拼接。

### 核心实体

- `walletBalance`：成员当前可用额度。
- `ownerPoolBalance`：群主当前可分配额度池。
- `members[]`：成员 ID、身份资料、游戏权限、当前额度和行为状态。
- `creditRequests[]`：上分 / 下分申请、金额、申请人、状态、时间、拒绝原因。
- `transactions[]`：只保存真正造成额度变动的已完成流水。
- `gameSettlements[]`：已结算的游戏盈亏；成员钱包可纳入净变动，但不混入群主上 / 下分审批。
- `rakeConfig` 与 `rakeLedger[]`：抽成设置和群主抽成记录，与成员钱包隔离。

### 状态与记账规则

```text
成员提交上分 / 下分
        ↓
creditRequests 新增 pending
        ↓
群主通过 ──→ 原子更新成员额度与群主额度池
        │                    ↓
        │              写入 transactions
        ↓
群主拒绝 ──→ request = rejected，不写入 transactions
```

- `pending` 只出现在待审核申请，不进入额度往来汇总。
- `approved` 必须同时更新申请、双方余额和已完成交易，不能只改其中一个页面。
- `rejected` 保留审计信息但不改变任何余额。
- 所有金额、计数、汇总和列表由同一状态派生；页面只负责渲染，不维护各自副本。
- 后续接后端时，通过操作必须支持幂等、防重复审批和余额不足的原子校验。

## Superseded Archive（历史依据，不得直接实施）

只有在追查设计原因、比较旧方案、处理回退或用户明确要求恢复旧版时才查阅本节。普通开发不得从这里抄实现。

### S-01 · Credit / 提款式 Wallet

- 旧方案：`可用 Credit ¥240`、申请 Credit、申请提款、累计 Credit 入账、累计提款、最多 5 条 Transaction，并排除游戏盈亏。
- 当前替代：当前额度 + 上分 / 下分 + 今日盈亏 / 今日未结 + 含游戏盈亏的额度往来。
- 恢复条件：只有 client 明确要求重新采用现金 / Credit 双层钱包模型时才重新评估。

### S-02 · 频道 Header 固定管理入口

- 旧方案：频道 Header 右上角「管理 + 红点」，聊天列表不显示管理入口；皇冠因容易被理解成 VIP 而淘汰。
- 当前替代：代码使用聊天列表置顶「幸运组 · 管理面板」并显示待审核数量。
- 皇冠仍是被否决方案，不可因视觉明显而自动恢复。

### S-03 · 审批双确认与原位完成态

- 旧方案：通过 / 拒绝均二次确认，拒绝原因可选并对成员可见，完成后卡片原位显示状态。
- 当前替代：即批即走，点击后直接处理、Toast、移除卡片并 auto-next。
- 若未来恢复确认，必须先重新确认资金风险、处理效率和拒绝原因业务要求。

### S-04 · 三 Tab 游戏厅

- 旧方案只有投注 / 自动投 / 聊天室。
- 当前替代为四 Tab，并加入查爆仓。

### S-05 · 旧自动投仪表盘

- `dashPlans[]` 旧仪表盘、Grid / List 切换、旧 L1 / L2 计划卡、旧分享下注和旧空态属于早期方案。
- 当前替代为三卡位策略中心、生命周期 Feed、本轮分享与套用保护。

### S-06 · 回收额度与冻结成员

- 旧「群主主动回收额度」已删除；当前由成员发起下分。
- 旧「冻结成员」已改为「停用游戏权限」；成员额度保留，已下注单照常结算。

### S-07 · 独立群主交易记录页

- 旧方案把交易记录作为独立页面或入口。
- 当前替代为管理中心首页内联「额度往来」，并在成员详情和钱包复用相同信息层级。

### S-08 · 旧视觉与组件规则

- Navy / Pink 主色、独立成员详情大字号、装饰性人物 / 饼图、审批圆形 ✓✕、为了统一而给每行加 chevron 等均已淘汰。
- 旧 pending 文案「处理中 / 待确认」已统一为「待审核」。
- 当前以共享蓝白设计语言、文字 CTA、明确层级和实际导航语义为准。

### S-09 · 分享卡隐藏本轮投入

- 旧方案展示精确本轮盈亏与策略动态，却隐藏个人投入金额，理由是保护个人资金。
- 当前替代：分享卡可以展示本轮总投入与本轮盈亏；真正需要保护的是钱包余额、额度记录、总资产和其他策略资金。
- 展示本轮投入不代表接管 Henry 的运行；直接套用会把公开的金额与风控规则复制到接收者自己的独立策略草稿，接收者也可先编辑，并须经过后续确认。

## Architecture (how the prototype works)
- One phone mock. Screens are `<div class="view view-NAME">`; only `.view.on` is shown.
- `views/*.js` 先把页面模板注册到 `window.IM168_VIEWS`，`shared/app.js` 启动时排序并注入 `.body`。
- `shared/app.js` 通过 document 级事件委托读取 `data-act="ACTION"` + `data-arg="VALUE"`，并由 `showView()` 维护页面、chrome、底部导航和 URL hash。
- **Chrome header** (`.ghead.chrome`, `data-mainviews="bet autos chat bust"`) 用于四个游戏厅 Tab；Round Bar 只在投注页显示。顺序为 game title / wallet pill → tabs → 投注页开奖栏。
  - **Title = current game name** (`.gname` swapped by `.phone[data-game]`: pk→`SG飞艇`, ssc→`时时彩`), with `▾` caret; tapping `.gtitle` opens 全部游戏 lobby (`data-arg=lobby`). **幸运组** (channel) sits muted beside it. The old standalone `SG飞艇▾` switcher in the roundbar was removed (title owns it now).
  - **Wallet pill** (`.bal`, `data-arg=wallet`): wallet SVG icon + 当前额度 `240,000.00`。显示在四个游戏厅 Tab。
  - **Balls** = rounded squares (`.bb`, single row, nowrap). Status bar uses real signal/wifi/battery SVGs. Subtle radial glow on `.ghead`. Tabs have a short centered underline.

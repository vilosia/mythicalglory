2026-08-12 · 建立唯一令牌来源（tokens.css）
---------------------------------------------------------------------
这一轮<不动任何一个 class、不改任何一屏的外观>，只解决「令牌到底以谁为准」。

【扫描出来的问题】
把 26 个页面 + 6 份 shared CSS 全量扫过一遍，量出来的事实：

  · 全项目 920 个不同的十六进制色值。按语义分桶：
      蓝 392 种 · 金/琥珀 145 种 · 中性 262 种 · 红 64 种 · 绿 57 种
  · var(--…) 引用 5,936 处 —— 令牌其实用得很勤，但同时长了一套平行的裸色值。
  · 35 种字号，其中 7 种是小数（9.5 / 10.5 / 11.5 / 12.5 / 13.5 / 14.5 / 15.5px）。
  · 28 种圆角；1,913 处间距不在 4px 网格上（10 / 9 / 11 / 6 / 7 / 14 / 13 / 5px 最多）。
  · 最要紧的一条：shared/design-tokens.css（v2.1，写得很认真）<管不到任何东西>。
    reference-theme.css 后加载，用 7 个 :root 把其中 23 个同名令牌又定义了一遍，
    每个最多 3 种取值（--blue 有 #126BFF / #0787d7 / #1677ee / #1d9bf0 四种写法）。
    实测：hall-plans.html 声明 --blue:#126BFF，页面真正渲染 #1677ee。
    --ink / --red / --win / --line / --radius-md 无一例外全部被改写。
    也就是说：那份「设计令牌」是一份<与成品对不上的文档>。

  ✓ 好消息：26 个页面<彼此是一致的>（同一组值赢下所有覆盖），
    所以这不是「各屏各色」，而是「文档说的和做出来的不是一回事」。

【这一轮做了什么】
  1. 新增 tokens.css（项目根目录）＝交付给前端的唯一词汇表。
     取值原则：<先照实记录，再谈修改>。每个值都是用 getComputedStyle
     从跑起来的原型里读出来的<今天真正渲染的那个值>，不是设计稿上的理想值。
     所以引入它不会让任何一屏变样（已逐项比对 26 个旧令牌，全部一致）。
  2. shared/design-tokens.css 退成<转接层>：旧名字 → 新令牌，自己不再定义值。
     旧名字一个都没删，5,936 处 var() 继续照常工作。
  3. 每个用到 shared 样式的页面，在<所有样式表之前>加一行
       <link rel="stylesheet" href="tokens.css">
     共 16 个产品页面。顺序很重要：tokens.css 必须最先，转接层随后覆写
     那几个同名不同义的（见下）。

【踩到的两个坑，记下来免得再试】
  · Chrome 在 file:// 下<不加载>跨目录的 @import。
    shared/design-tokens.css 里写 @import url("../tokens.css") ——
    styleSheets 里根本找不到那份表，所有新令牌算出来是空的。
    放到 styles.css 第一行同样不行（也是 ../）。
    最后用页面上的 <link href="tokens.css">（同目录，不带 ../）才成立。
    ⚠ 别再把它改回 @import：本地双击打开就会静默失效，而且不报错。
  · --muted <同名不同义>，是全套里最容易接反的一处：
      存量代码里 --muted 是「次要文字色」；
      新词汇表里 --muted 是「浅灰底色」、--muted-foreground 才是文字。
    所以转接层保留存量语义（文字），并把底色那一档另存为 --x-surface-sunken；
    --fill 必须引用 --x-surface-sunken，写 var(--muted) 会拿到文字色当底色。

【唯一一处刻意的取值改动】
  --danger 与 --red 在 v2.1 里是同一个值，但 reference-theme 只改写了 --red，
  于是产品里<同时存在两个红>（#EF3939 / #ee3d49），肉眼几乎分不出，语义已经分叉。
  这一轮把 --danger 并入 --destructive（#ee3d49），红色从此只有一个。

【还没做，需要拍板或排期】
  A. 五条可访问性问题，写在 tokens.css 文件末尾：
       ① --danger/--red 两个红（已在本轮合并）
       ② --warning 被 reference-theme 改坏对比度（4.65:1 → 2.74:1，不达标）
       ③ 小字号盈亏不达标（--success 3.37:1 / --destructive 3.89:1，
          大数字过关、11–14px 的不过）
       ④ 焦点样式只覆盖三个局部组件，而且<输入框的 outline 被 !important 关掉了>
       ⑤ 182 个可点元素里 30 个高度不足 44px，最小 16px
     ②③是「改一行令牌值」；④⑤是「补规则」。都没有擅自动 —— 那是改设计。
  B. reference-theme.css 里那 7 个 :root 还在。它们现在与 tokens.css 取值一致，
     所以留着不会出错，但只要有人去改其中一个，两边就又会分叉。
     建议排一轮专门删掉它们（删之前逐个页面截图比对）。
  C. 920 个裸色值、7 种小数字号、1,913 处非 4px 间距还在存量 CSS 里。
     这不是一轮能清的，建议的顺序：先冻结（新代码只准用令牌），
     再按页面逐屏收敛，每收一屏跑一次 validate-handoff。

2026-08-12 · 列表视图：缩略图当放大低透明度底图（08-12J）
---------------------------------------------------------------------
Hector 想试试这个效果。结论：<能做，而且明显更有意思，但受素材限制>。

做法：JS 把缩略图地址挂在卡片的 --gx-thumb 上，列表视图用 ::before 铺同一张图，
放大到行高 240%、从右侧出画、mix-blend-mode:multiply、opacity .42，
再加一层左侧渐隐遮罩。双列视图不受影响。

踩过的四个坑（都是「不报错、只是不生效」那一类）：
  1. 自定义属性里写相对 url() → 相对<使用它的样式表>解析，而使用它的是 shared/hall.css，
     于是 'shared/game-icons/x.png' 被解成 shared/shared/game-icons/x.png，静默 404。
     必须用 img.src（已解析成绝对地址）。
  2. .gx-card::after 被 reference-theme 用两条 !important 关掉了（content:none;display:none），
     所以白幕做在 ::after 上<根本不会出现>。改成把渐变做进 ::before 的第二层背景，
     后来又改成用 mask。
  3. 百分比背景定位做不出「出画」：`right -4%` 被算成 104%，图比容器窄时会被整块推出框外。
     要出画只能用像素偏移（right -18px）。
  4. 这些缩略图<不是白底、是淡蓝底>（四角 255,255,255，中间取样 214,242,251）。
     所以低透明度叠加会压出一个<看得见的矩形>，像贴错图。multiply 只解决一半，
     最后靠左侧渐隐遮罩把矩形边界溶掉。

⚠ 真正的解法是<素材>：要透明底（只有物件、没有方形底色）的 PNG。
  有了透明底就不需要 multiply 也不需要遮罩，效果还会更干净、更可控。
  现在这一版是<在现有素材上能做到的最好效果>，建议下一版素材直接出透明底。
⚠ 副作用：倒计时与角标现在压在图上。图很淡（.42 ＋ multiply）所以还读得清，
  但若换成更深的素材要重新评估对比度。

2026-08-12 · 分享卡是冻结快照，卡上要说清楚（08-12P）
---------------------------------------------------------------------
Hector：分享出去的卡不是活卡，是定格。卡上要有「什么时候冻的」与「指的是哪一段期号」，
否则看的人会以为它还在跑、也不知道那条曲线画的是哪几期。

这其实是 Alex 08-11 就提过的一条（「快照时间 ＋ 一句『分享后不再更新』…
要写在卡上，不能让人以为它在跑」）。08-11 三稿把「快照 14:32」删掉了，理由是
它与卡头右上角的时间重复 —— 理由当时成立，但连「冻结」这件事一起带走了，
含义只剩页顶那枚 ⓘ。C 栏把卡做成与策略页那张一模一样之后，这个洞更大：
卡看起来就是活的，还带一颗「跟这一套」。

补的两个标记<b>都带新信息</b>，不再是重复时间：
  ① 头一行右端一枚灰 chip「快照」—— 零高度成本，一眼可辨。
  ② 曲线正下方的<b>期号轴</b>：左「第00001–00089 期」、右「14:32 定格 · 之后不再更新」。
     时间戳答不了「是哪一期」，期号才答得了；放在曲线下面，正是看图的人起疑的位置。
  ③ 越旧越要说：超过一小时的卡右端转琥珀「已过 3 小时」。C 栏第三张（11:20 的官方卡）
